## 2 WMA实验设置与优化方法

实验使用020机RTX 4090 24 GB、16 vCPU、120 GB内存。基线与优化使用同一UnifoLM-WMA-0-Dual权重、同一20项manifest与官方评分路径。基线开启FP16/AMP，单纯开启autocast不计入个人优化。

| 固定项 | 正式设置 |
| --- | --- |
| 精度 | FP16 autocast  不使用低于16-bit精度 |
| 采样 | DDIM 50步  eta 1  seed 123 |
| 视频 | 512×320  8 fps |
| 交互轮数 | 按manifest保持7  8  11或12轮 |
| 完整帧数 | 对应112  128  176或192帧 |
| CPU线程 | 优化运行8线程  interop 2 |


基线流程逐项启动并加载模型。分析后，优化使用持久化模型生成19项，减少重复导入与模型初始化，并控制CPU数学库线程争用，减少不参与正式输出的诊断保存。正式视频内容和规定输出不变。

质量敏感项unitree_z1_dual_arm_stackbox_v2/case1在正式v4开始前固定采用独立确定性FP16子进程：模型初始化后、准备输入前重置seed，完成一次完整生成后退出并释放GPU，再加载其余19项模型。没有依据本轮GT评分挑选候选，没有生成重试。

## 5 QiboTN官方CPU路径、源码改动与压力验证

源码来自qiboteam/qibotn官方仓库，保留上游提交7ebbd4d4a00f37b898c552922953591b78b0af7e及fork历史。当前性能实验通过QiboTN Quimb NumPy CPU执行，不使用qibojit、cuQuantum、GPU或外部态矢量模拟计时。独立Qibo NumPy完整态仅用于正确性参照，排除在两路性能计时之外。

当前六模块源码包含共享Pauli收缩环境、等价单比特门合并、精确QR/等距因子内核、私有工作区内存复用、六门前瞻逻辑路由、经GF(2)完整算子验证的CNOT块编译，以及保留不对易依赖的有界混合门调度。静态调度不读取振幅、答案、线路名称或实测速度，不按GT选择候选。截断、非NumPy及不支持操作保留原框架路径。相关线性代数和门综合算法为已有方法，个人贡献为具体实现、保守分发、框架接入和验证，不能冒称发明这些数学算法。

当前公平基线仅对固定官方源码修复一次属性拼写，未加入旧守护基线的额外范数收缩。两路使用complex128、cutoff=0、max_bond=None、同一输入、同一CPU集合[2,4,6,8]、同一BLAS单线程；每次重新准备MPS并计算原四项ZZ。生产回归322项通过，研究/审计73项通过。

## 瓶颈与个人优化

25-qubit线程扫描中，1、2、4、8、16线程单次耗时约为23.69、41.15、53.10、81.95、128.61 s。重复的小中型张量与SVD运算中，较大的线程团队带来显著调度和同步开销，形成此机器上的线程争用瓶颈。

独立新进程在相关环境变量未设置时检测到OpenBLAS默认20线程。历史实验在导入NumPy与Quimb前固定数学库线程为1，说明小中型张量运算可能出现线程调度瓶颈。当前源码性能比较双方均使用1线程，故不将消除病态多线程开销计入新源码倍率，也不将框架原生MPS相对态矢量的优势记作个人贡献。

同时修复Quimb期望值路径读取contractions_optimizer属性的问题，并增加回归测试。基线与优化均使用相同修复后的路径，该源码修复不单独冒充7.0260×的性能来源。
