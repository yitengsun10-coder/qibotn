# 孙逸腾 QiboTN：精确单位结构验证器的内存优化阶段记录

2026-10-10，北京时间。PDF及老师截图优先；原高纠缠精确30比特完整验证仍是用户硬验收项。本轮是源码研究改进与本机验证，不是最终赛题完成报告。

## 本轮实际推进

新增`candidate_analytic_identity.py`，在既有精确受控rank2路径上，去掉单位等距张量验证器的整张量数值快照，改成弱引用加分块、逐值检查。没有改线路、删门、截断bond、降低complex128精度或切换量子仿真后端。可与原调度或短CNOT调度组合；当前研究入口未接入生产。

这项优化针对的是通用的已生成单位等距张量，不识别原30线路、qubit数量、预定答案或计时结果。收益取决于运行中实际出现的单位结构及张量大小，不保证所有线路更快。

## 原验证器为什么占内存

现有`StructuredExactKernelMPS._put`在标记单位结构时保存`data.copy()`，后续使用前通过数组身份及逐值比较防止外部原地修改。这个安全目的必须保留，但大张量的快照和比较临时量会增加内存。

新验证器保留两个必要条件：

1. 标签记录的弱引用必须仍指向当前站点数组；换成另一数组，即使值相同，也使原标签失效。
2. 对全部现值精确检查左单位结构`A[l,r,p]=δ(r,2l+p)`或右单位结构`A[l,r,p]=δ(l,2r+p)`。分块统计全部非零值，再逐个检查规定位置严格为1，不用容差或数值秩猜测。

微小非零、非1对角、NaN/Inf以及错误形状均不能通过。外部修改导致失效后，原通用收缩路径仍计算修改后的真实态。标签不强持有被替换的旧数组，也不把外部数组改成只读。

这只消除验证器快照，不消除显式MPS张量、QR工作区、合并矩阵或其他临时数组。原30尺寸预检中的42.67 GiB显式态表示仍然存在，不能把本项直接说成原线路已适配60 GiB实例。

## 隔离分配微测结果

最新证据：`results/identity_guard_memory_v2_20261010.json`。输入是一个形状`[512,1024,2]`、complex128、16 MiB的确定性单位等距张量，置于键维度一致的合成三站点表示中。**本微测没有执行量子线路，也不是归一化量子工作负载。** NumPy 2.2.6、Quimb 1.13.0；先验证NumPy分配可被tracemalloc跟踪，再比较两种验证器。

| 项目 | 旧快照验证器 | 新分块验证器 |
| --- | ---: | ---: |
| 对同一单位结构精确识别 | 通过 | 通过 |
| 附着的整张量验证快照 | 16777216 B（16 MiB） | 0 B |
| 本次跟踪到的额外分配峰值 | 17959672 B（约17.13 MiB） | 31992 B（约31.24 KiB） |
| 验证器扫描视图上限 | 未采用新分块策略 | 1048576 B（1 MiB） |

tracemalloc数值不是进程RSS，不含输入张量和测试前分配，也不是全线路峰值。1 MiB是每个扫描视图/选择的声明上限，不是整个进程或所有临时对象总内存上限。**上述内存微测不形成量子加速比，不外推成原30整体节省多少GiB。**

微测记录六份相关源码SHA256和确定性输入哈希，打包前核验源码未变、输入矩阵哈希/字节数、两方法快照策略、扫描边界及统计字段。首次微测与补充源码声明后的v2均保留，最新以v2为准。
